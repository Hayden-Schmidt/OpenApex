# Page 2 — Idle Screen

## Requirements

Screen shown once the app is loaded, before navigation has started. Must be part of the **state
machine** so screens can still switch later (compass, odometer, music controls — screens not yet
introduced in this brief).

**Key components:**

- Time display.
- An icon indicating **phone/connection status**, rendered in the theme colour.

**Simple:** static screen with a phone icon that updates when connected/disconnected via BLE.

**Rich:** same for now; more actions TBC.

## Reference

Beeline Moto 2 idle screen (do not copy exactly, no motorcycle icon) — style reference only.

## Current code status: ⬜ not rendered (state exists)

The idle **state** exists in the model, but nothing renders it.

- `view_state_t` (`firmware/main/view_state.h`) defines `VIEW_IDLE = 0` — "no active navigation, no
  fabricated values".
- `terminal_view_state_t` carries `battery_percent` and (implicitly via BLE connection) the phone
  status, but there is **no dedicated connection-state field** in the struct — connection status is
  not yet surfaced to the GUI (the BLE layer in `firmware/main/ble_link.c` logs connect/disconnect
  but does not publish it into `shared_view`).
- `gui_app_update()` (`firmware/gui/gui_app.cpp`) is a no-op, so `VIEW_IDLE` renders nothing.

**Backend gaps flagged:**

1. A **connection-state signal** (BLE connected/disconnected) must be plumbed from
   `ble_link.c` into `terminal_view_state_t` (or a side channel) so the idle icon can reflect it.
2. **Time source** for the clock — the C3 has no RTC (`board_profile.h`: `BOARD_HAS_IMU 0`, no RTC
   pinout); S3 has a PCF85063 RTC. Phone-side time sync is a backend item for post-UI sprint.
